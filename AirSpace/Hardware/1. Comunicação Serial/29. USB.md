# Pinagem USB (resumo útil)

## USB 2.0 (A, B, Mini/Micro)

|Pino|Nome|Função|
|---|---|---|
|1|**VBUS**|+5 V (alimentação do periférico)|
|2|**D-**|Dados diferencial (USB 1.1/2.0)|
|3|**D+**|Dados diferencial (USB 1.1/2.0)|
|4|**GND**|Terra|
|—|**Shield**|Blindagem do cabo (carcaça)|

_(Conectores A, B, mini-B e micro-B têm esses 4 sinais. No micro-B existe um pino “ID” interno para OTG, mas em adaptadores seriais comuns ele não é usado.)_

## USB-C (o que interessa para USB 2.0)

- Ainda usa **D+ / D-** (linhas A6/A7 e B6/B7 — espelhadas por causa da reversibilidade).
- **VBUS** (+5 V), **GND**.
- **CC1/CC2**: resistores/handshake para anunciar função e corrente.
- SuperSpeed (TX/RX pares) só é usado por dispositivos USB 3.x; a maioria dos **USB-Serial** usa **apenas USB 2.0** (D+/D-).
# Como a conversão USB → RS-232 funciona

**Não existe “mapeamento de pinos”** direto entre USB e RS-232 — é uma **ponte de protocolo + conversão elétrica**:

1. **Controlador USB-Serial**  
    Um CI (ex.: **FT232R**, **CP2102**, **CH340**, **PL2303**) se conecta ao **USB (D+/D-)**, enumera no SO e aparece como **porta COM** (CDC-ACM/driver próprio).
    
    - No PC você escreve/le o COMx.
        
    - O CI faz **bufferização**, **geração de baud**, **8N1/paridade**, **RTS/CTS, DTR/DSR, DCD, RI** (linhas “modem”).
        
2. **Níveis elétricos**  
    O chip USB-Serial tipicamente gera **UART TTL** (0–3,3 V ou 0–5 V).  
    Para virar **RS-232 real** (±3…±12 V e **invertido**), entra um **transceiver** tipo **MAX3232** (ou integrado no próprio dongle).
    
    - **TTL 1/0** → **RS-232 −/+** (invertido e com amplitude maior).
        
    - Linhas de controle (**RTS, CTS, DTR, DSR, DCD, RI**) também passam pelo transceiver.
        
3. **Fluxo lógico**
    
    - **PC → USB (pacotes bulk)** → **CI USB-Serial** → **gera UART** → **transceiver RS-232** → **CLP**.
        
    - **CLP → RS-232** → **transceiver** → **UART do CI** → **USB** → **PC**.  
        Tudo com **buffers FIFO**, por isso é comum você “dar write()” em blocos e o hardware “despejar” em UART no ritmo do baud.
        
4. **Handshaking**
    
    - Se você habilitar **RTS/CTS** no driver, o CI mapeia para as linhas RS-232 correspondentes.
        
    - **DTR/DSR/DCD/RI** podem ser lidos/alterados via IOCTLs/`EscapeCommFunction`.
        
5. **Alimentação**
    
    - O dongle é alimentado pelo **VBUS 5 V** do USB. Alguns têm **isolação** (opcional, melhor para CLPs).
