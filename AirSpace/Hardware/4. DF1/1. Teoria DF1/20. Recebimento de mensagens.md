O receptor mantém um registro da última resposta enviada ao
transmissor. O valor dessa resposta é DLE ACK ou DLE NAK.
É inicializado como DLE NAK. Quando um DLE ENQ (consulta) é
recebido do transmissor, o receptor envia o valor da última
resposta.
O receptor ignora todas as entradas até que um DLE STX ou DLE ENQ
seja recebido. Se algo diferente de um DLE STX ou DLE ENQ
for recebido no caminho um, o receptor define a variável da última
resposta como NAK.

| Quando este símbolo é recebido do transmissor: | então:                                                                                                      |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| DLE ENQ                                        | A última resposta é enviada<br>e o receptor<br>continua aguardando<br>a entrada de dados.                   |
| DLE ACK                                        | O BCC/CRC e o buffer de mensagens são redefinidos e o receptor começa a construir uma mensagem de resposta. |
Ao construir uma mensagem de resposta, todos os símbolos de dados são
armazenados no buffer de mensagens e adicionados ao BCC/CRC.
Se o buffer transbordar, o receptor continua somando o
BCC/CRC, mas os dados são descartados.
Se um erro de paridade, estouro de buffer, enquadramento ou handshake do modem for
detectado, ele é registrado.
Se um símbolo de controle diferente de DLE STX ou DLE ETX for
recebido, a mensagem é abortada e um DLE NAK é enviado
para o transmissor. Quando DLE STX ou DLE ETX é recebido,
o sinalizador de erro, o BCC/CRC, o tamanho da mensagem e o
endereço (opcionalmente) são verificados. Se algum dos testes falhar,
um DLE NAK é enviado.
GET_CHAR é definida como uma função dependente da implementação
que retorna um byte de dados da interface de hardware de comunicação.
