>Conectando um módulo de interface a um computador, devemos programar o computador para entender e emitir as sequências de caracteres de protocolo adequadas. 
 
Um protocolo de enlace é um conjunto de regras de programação para interpretar os sinais transmitidos por um enlace físico. Um protocolo, como DF1:

>Carregar uma mensagem, sem erros, de uma extremidade do link para a outra, não se preocupar com conteúdo da mensagem, a função da mensagem. ou o objetivo final da mensagem. Com o protocolo DF1 `full-duplex`, faz isso anexando um caractere de verificação  `(BCC)` ou caracteres de verificação `(CRC)` ao final de cada comando e resposta. O dispositivo que recebe o comando ou resposta verifica o `BCC` ou `CRC` e retorna um `ACK`, se o `BCC` ou `CRC` for aceitável, ou um NAK, se o `BCC` ou `CRC` não verificar.

>indica falha com um código de erro internamente, o protocolo de link deve delimitar mensagens, detectar e sinalizar erros, tentar novamente após erros e controlar o fluxo de mensagens

O protocolo DF1 é um protocolo de camada de enlace de dados Allen-Bradley que combina recursos das subcategorias D1 (transparência de dados) e F1 (transmissão simultânea bidirecional com respostas incorporadas) da especificação ANSI x3.28. Existem duas categorias de Protocolo DF1:

- Protocolo `half-duplex` (comunicação ``mestre-escravo``)
- Protocolo `full-duplex` (comunicação ponto a ponto)

#### Protocolo `half-duplex`
> O protocolo  `half-duplex` é um protocolo `multidrop` para um escravo e um ou mais escravos. Com o protocolo `half-duplex`, podemos ter de 2 a 255 nós conectados simultaneamente em um único link; Esse link opera com todos os nós conectados por meio de modems `half-duplex`. (Para obter uma lista de dispositivos que podem ser usados como mestres e escravos)

para implementar o protocolo `half-duplex`, usamos as seguintes características de comunicação:

- 8 bits por caractere
- sem paridade
- 1 bit de parada

Quando usarmos o protocolo `half-duplex`, o ambiente pretendido é um link `multidrop` com todos os nós conectados por meio de modems `half-duplex`. A menos que haja apenas um escravo diretamente conectado a um mestre, você deve usar um modem, seus modems devem suportar estes sinais:
• request-to-send (RTS)
• clear-to-send (CTS)
• data-carrier-detect (DCD)
• data-set-ready (DSR)
• data-terminal-ready (DTR)


#### Protocolo `full-duplex`
Use o protocolo`` full-duplex:``
• através de uma ligação ponto a ponto que permite a transmissão simultânea bi-direccional
• através de um link ``multidrop`` onde os módulos de interface são capazes de arbitrar a transmissão no link
• para aplicações de alto desempenho onde é necessário obter o maior rendimento possível do meio disponível, Se você conectar um módulo de interface a outro módulo de interface de comunicação Allen-Bradley, os módulos lidam automaticamente com a arbitragem de link.
