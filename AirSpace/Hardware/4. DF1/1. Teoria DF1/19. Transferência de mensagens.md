No protocolo full-duplex, as mensagens são enviadas da origem (parte do
software que fornece o pacote de mensagens) através de um transmissor
(dispositivo que envia dados) e, em seguida, de um receptor (dispositivo que recebe
dados) até o destino (parte do software que aceita os dados recebidos).

>Sempre que a fonte da mensagem puder fornecer um pacote de mensagem e o
transmissor não estiver ocupado, ele envia um quadro pelo link para o endereço
de destino. Em seguida, inicia um temporizador e aguarda uma resposta.


| Quando esta resposta for recebida pelo endereço de destino. | o pacote de mensagens                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DLE ACK                                                     | A mensagem foi transferida com sucesso.<br>Após sinalizar à origem da mensagem que o pacote de mensagem foi transmitido com sucesso, o transmissor prossegue com o próximo pacote de mensagem.                                                                                                                                                                                                                                                                       |
| DLE NAK                                                     | A mensagem é retransmitida. O transmissor reinicia o temporizador e aguarda novamente por uma resposta. Se receber um DLE ACK, o transmissor inicia um novo temporizador.<br>Este processo pode ser repetido várias vezes. É possível definir um limite para o número de vezes que uma mensagem pode ser retransmitida para cada módulo.<br>Se esse limite for excedido, a origem da mensagem é informada da falha e o transmissor prossegue com a próxima mensagem. |
>Se o tempo limite expirar antes de uma resposta ser recebida, o transmissor envia
 um DLE ENQ para solicitar a retransmissão da última resposta. Ele reinicia
 o temporizador e aguarda uma resposta.
 Você também pode definir um limite para o número de tempos limite permitidos por
 mensagem. Se o limite de solicitações (ENQ) for excedido, o transmissor sinaliza
 para a origem da mensagem que a transmissão falhou e prossegue para a próxima mensagem.
 Existem três respostas definidas: DLE ACK, DLE NAK, DLE ENQ.
 Se o transmissor receber uma resposta diferente, ele a ignora.

TRANSMITTER is defined as

    loop
        Message= GET-MESSAGE-TO-SEND -- DADOS A SEREM ENVIADOS
        Status=TRANSFER(Message) -- ENVIAR A MENSAGEM
        SIGNAL-RESULTS(Status) -- STATUS DO ENVIO
    end loop
loop
WAIT for response on path 2 or timeout.
if received DLE ACK then return SUCCESS -- verificar se o envio da mensagem foi ACK
else
    if received DLE NAK then -- verifica se o sinal foi NAK
        if nak-limit is exceeded then return FAILURE -- verifica a quantidade de NAK recebido se igual ao limite, erro no envio de mensagem
        else
            begin
                count NAK re-tries; -- contador de NAK
                SEND-MESSAGE(message); -- reevia mensagem
                start timeout -- conta um tempo para reenvio
        end
    else  -- se não receber nem ACK e nem NAK, verifica se o tempo para um resposta
        if timeout -- se o tempo é excedido enviar ENQ
            if enq-limit is exceeded then return FAILURE -- verifica a quantidade de ENQ recebido se igual ao limite, erro no envio de mensagem
        else
            begin
                count ENQ re-tries; -- contador ENQ
                send DLE ENQ on path 1; -- reenvia mensagem
                start timeout -- conta tempo para reenvio
            end
        end loop
SEND (message) is defined as -- função responsavel por calculo de bcc e envio dos bytes
    begin
        BCC = 0
        send DLE STX on path 1
        for every byte in the message do
            begin
                add the byte to the BCC;
                send the corresponding data symbol
on
                path 1
            end
        send DLE ETX BCC on path 1
    end
GET-MESSAGE-TO-SEND -- função responsavel por estruturar os dados apra envio
    This is an operating-system-dependent interface
    routine that waits and allows the rest of the
    system to run until the message source has supplied
    a message to be sent.
SIGNAL-RESULTS -- função responsavel por receber os dados de retorno do recepetor
    This is an implementation-dependent routine that
    tells the message source of the results of the
    attempted message transfer.
WAIT -- função para esperar a resposta
    This is an operating-system-dependent routine
    that waits for any of several events to occur
    while allowing other parts of the system to run.
TRANSFER (Message) is defined as -- função que chama a função de envio de mensagem, começa o tempo de envio, define limite de NAK e ENQ, personalisavel
    initialize nak-limit and enq-limit
    SEND(Message)
    start timeout
