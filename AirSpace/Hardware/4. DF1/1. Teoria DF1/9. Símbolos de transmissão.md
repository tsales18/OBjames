Um símbolo é uma sequência de um ou mais bytes com um significado específico para o protocolo de link. Os caracteres componentes de um símbolo devem ser enviados um após o outro sem outros caracteres entre eles. O protocolo DF1 combina os caracteres listados acima em símbolos de controle e dados:
- Os símbolos de controle são símbolos fixos exigidos pelo protocolo DF1 para ler uma mensagem específica
- Os símbolos de dados são símbolos variáveis que contêm os dados do aplicativo para uma mensagem específica


`half-duplex`:

| Símbolo         | Tipo                | Significado                                                                                                                                                                                                                                                 |
| --------------- | ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DLE SOH         | Símbolo de controle | Simbolo que indica o inicio de uma mensagem mestra                                                                                                                                                                                                          |
| DLE STX         | Símbolo de controle | Símbolo do remetente que separa o multidropheader dos dados                                                                                                                                                                                                 |
| DLE ETX BCC/CRC | Símbolo de controle | Simbolo do remetente que encerra uma mensagem                                                                                                                                                                                                               |
| DLE ACK         | Símbolo de controle | Símbolo de resposta que sinaliza que uma mensagem foi recebida com sucesso                                                                                                                                                                                  |
| DLE NAK         | Símbolo de controle | Comando de redefinição de link global emitido apenas pelo mestre. Faz com que os escravos cancelem todas as mensagens que estão prontas para serem transmitidas ao mestre. Normalmente, o escravo retorna a mensagem e um código de erro para o originador. |
| DLE ENQ         | Símbolo de controle | Símbolo do remetente, emitido apenas pelo mestre, que inicia um comando de pesquisa.                                                                                                                                                                        |
| DLE EOT BCC     | Símbolo de controle | Símbolo de resposta usado por escravos como resposta a uma enquete quando eles não têm mensagens para enviar                                                                                                                                                |
| STN             | Símbolos dados      | Número da estação do nó escravo em seu link `half-duplex`                                                                                                                                                                                                   |
| APP DATA        | Símbolos dados      | Caracteres únicos com valores 000F e 11FF, inclui dados da camada de aplicativo, incluindo programas de usuário e rotinas de aplicativos comuns. Um dados 1016 é enviado as 10 10 (DLE DLE).                                                                |
| DLE DLE         | Símbolos dados      | Representa o valor de dados ou valor STN de 1016                                                                                                                                                                                                            |

| --------------- | ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DLE STX         | Símbolo de controle | Símbolo do remetente que indica o inicio de um quadro de um frame de mensagem.                                                                                                               |
| DLE ETX BCC/CRC | Símbolo de controle | Símbolo do remetente que encerra um quadro de mensagem.                                                                                                                                      |

| DLE DLE         | Símbolos dados      | Representa o valor de dados ou valor STN de 1016                                                                                                                                             |

Sequência de bytes, bytes de controle e bytes de dados:
`10 01 02 30 31 32 10 03 A5`

| Bytes    | Interpretação                   |
| -------- | ------------------------------- |
| 10 01    | `DLE SOH` → início de cabeçalho |
| 02       | Data: 0x02 (código de estação)  |
| 30 31 32 | Dados ASCII ‘0’, ‘1’, ‘2’       |
| 10 03    | `DLE ETX` → fim do texto        |
| A5       | BCC (checksum)                  |

``protected typed logical read with three address fields:``
 ![[Pasted image 20251011164849.png]]

| Ordem  | Campo                 | Tamanho (bytes) | Significado técnico                     | Explicação detalhada                                                                                                                                                                                                        |
| :----- | :-------------------- | :-------------- | :-------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1**  | `DLE SOH` (0x10 0x01) | 2               | _Start of Header_                       | Indica o início do cabeçalho da mensagem. O **DLE** (Data Link Escape = 0x10) é um prefixo especial que “escapa” o byte de controle seguinte (**SOH = 0x01**). O receptor sabe que **a partir daqui começa um novo frame**. |
| **2**  | `DST`                 | 1               | Destination Node                        | Número da estação **destino** — o endereço do equipamento que deve responder. Exemplo: se for 0x00, é o CLP mestre; se for 0x02, é um escravo.                                                                              |
| **3**  | `SRC`                 | 1               | Source Node                             | Número da estação **origem** — quem está enviando a mensagem.                                                                                                                                                               |
| **4**  | `CMD`                 | 1               | Command                                 | Código da função/protocolo. Define o que será feito (por exemplo: leitura, escrita, diagnóstico, etc.). Exemplos: `0x0F` = Protected Typed Logical Write, `0x0E` = Protected Typed Logical Read.                            |
| **5**  | `STS`                 | 1               | Status                                  | Usado **somente nas respostas**. O CLP retorna aqui um código de erro ou 0x00 se tudo ocorreu bem. (Durante o envio, esse byte geralmente é 0x00 ou omitido.)                                                               |
| **6**  | `TNSL`                | 1               | Transaction Sequence Number (Low byte)  | Número de sequência da transação (parte baixa). Serve para **sincronizar requisições e respostas**: o mestre envia um número, e o escravo o repete na resposta.                                                             |
| **7**  | `TNSH`                | 1               | Transaction Sequence Number (High byte) | Parte alta do número de sequência TNS. Os dois bytes juntos formam um identificador de 16 bits para a transação.                                                                                                            |
| **8**  | `FNC`                 | 1               | Function/Subcommand                     | Código da subfunção associada ao comando principal. Por exemplo, em um comando de leitura, indica **o tipo de arquivo** (dados, status, bits, etc.).                                                                        |
| **9**  | `DADOS`               | Variável        | Data payload                            | O **conteúdo útil**: endereço lógico, número de elementos, dados a serem escritos ou lidos. É o corpo principal da mensagem.                                                                                                |
| **10** | `DLE ETX` (0x10 0x03) | 2               | _End of Text_                           | Indica o fim dos dados. Assim como o `DLE SOH` indica o começo do cabeçalho, o `DLE ETX` marca o fim da parte útil.                                                                                                         |
| **11** | `BCC`                 | 1               | Block Check Character                   | Byte de verificação (checksum). Calculado fazendo o **soma (com complemento de dois)** de todos os bytes entre o `DLE SOH` e o `DLE ETX`. Se a soma for incorreta, o receptor rejeita o frame.                              |

|Parte|Analogia|
|:--|:--|
|`DLE SOH`|“Começo da carta”|
|`DST` + `SRC`|“Para” e “De” no envelope|
|`CMD` + `FNC`|“Tipo de pedido” (ex: leia, escreva, status)|
|`DADOS`|“Conteúdo da mensagem”|
|`DLE ETX`|“Fim da carta”|
|`BCC`|“Assinatura de verificação” — confirma que ninguém alterou o conteúdo|
## Estrutura de Dados:
![[Pasted image 20251011183715.png]]

| Ordem     | Nome                   | Tamanho (bytes) | Descrição                                                                                                  |
| :-------- | :--------------------- | :-------------- | :--------------------------------------------------------------------------------------------------------- |
| **1**     | **Byte size**          | 1               | Quantos bytes cada elemento tem (ex: 2 bytes para inteiros, 4 para floats).                                |
| **2**     | **File number**        | 1               | Número do arquivo no CLP (ex: arquivo 7 → N7, arquivo 8 → F8).                                             |
| **3**     | **File type**          | 1               | Tipo do arquivo: • `0x89` = Integer (N) • `0x8A` = Floating Point (F) • `0x85` = Bit (B).                  |
| **4-5**   | **Element number**     | 2               | Endereço do elemento dentro do arquivo (ex: `N7:10` → elemento 10 → `0x0A 0x00`). Ordem _low-byte first_.  |
| **6-7**   | **Sub-element number** | 2               | Usado em arquivos com estrutura composta (geralmente 0x00 0x00 para elementos simples).                    |
| **8...n** | **Data (opcional)**    | Variável        | Presente apenas em comandos **de escrita**. Contém os valores reais a serem gravados (em _little endian_). |
Lendo de N7:0
`10 02 00 0E 00 01 00 A2 02 07 89 00 00 00 00 10 03 5C`

| Campo   | Valor               | Descrição                                |
| :------ | :------------------ | :--------------------------------------- |
| `10 01` | `DLE SOH`           | Início do cabeçalho                      |
| `00`    | DST                 | CLP destino                              |
| `01`    | SRC                 | Estaçãde origem                          |
| `0E`    | CMD                 | Leitura lógica protegida                 |
| `00`    | STS                 | (não usado em requisição)                |
| `01 00` | TNS                 | Número de sequência                      |
| `A2`    | FNC                 | Subfunção (Protected Typed Logical Read) |
| `10 02` | DLE STX             | Inicio da mensagem                       |
| `02`    | Byte size = 2       | Cada elemento = 2 bytes                  |
| `07`    | File number = 7     | Arquivo N7                               |
| `89`    | File type = Integer |                                          |
| `00 00` | Element number = 0  | N7:0                                     |
| `00 00` | Sub-element = 0     |                                          |
| `10 03` | DLE ETX             | Fim da mensagem                          |
| `5C`    | BCC                 | Checksum                                 |
