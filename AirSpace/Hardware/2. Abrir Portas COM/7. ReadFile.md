Lê dados do arquivo especificado ou do dispositivo de entrada/saída (E/S). As leituras ocorrem na posição especificada pelo ponteiro do arquivo, se suportado pelo dispositivo.

Esta função foi projetada para operações síncronas e assíncronas. Para uma função semelhante projetada exclusivamente para operações assíncronas, consulte [ReadFileEx](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-readfileex)

```
BOOL ReadFile(
  [in]                HANDLE       hFile,
  [out]               LPVOID       lpBuffer,
  [in]                DWORD        nNumberOfBytesToRead,
  [out, optional]     LPDWORD      lpNumberOfBytesRead,
  [in, out, optional] LPOVERLAPPED lpOverlapped
);
```
## Parâmetros

`[in] hFile`

Um identificador para o dispositivo (por exemplo, um arquivo, fluxo de arquivos, disco físico, volume, buffer de console, unidade de fita, soquete, recurso de comunicação, slot de correio ou pipe).

O parâmetro _hFile_ deve ter sido criado com acesso de leitura. Para obter mais informações, consulte [Direitos de Acesso Genéricos](https://learn.microsoft.com/en-us/windows/win32/SecAuthZ/generic-access-rights) e [Segurança de Arquivos e Direitos de Acesso](https://learn.microsoft.com/en-us/windows/win32/FileIO/file-security-and-access-rights) .

Para operações de leitura assíncronas, _hFile_ pode ser qualquer identificador aberto com o sinalizador **FILE_FLAG_OVERLAPPED** pela função [CreateFile](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilea) ou um identificador de soquete retornado pela função [socket](https://learn.microsoft.com/en-us/windows/win32/api/winsock2/nf-winsock2-socket) ou [accept](https://learn.microsoft.com/en-us/windows/win32/api/winsock2/nf-winsock2-accept) .

`[out] lpBuffer`

Um ponteiro para o buffer que recebe os dados lidos de um arquivo ou dispositivo.

Este buffer deve permanecer válido durante toda a operação de leitura. O chamador não deve usá-lo até que a operação de leitura seja concluída.

`[in] nNumberOfBytesToRead`

O número máximo de bytes a serem lidos.

`[out, optional] lpNumberOfBytesRead`

Um ponteiro para a variável que recebe o número de bytes lidos ao usar um parâmetro _hFile síncrono._ **ReadFile** define esse valor como zero antes de realizar qualquer trabalho ou verificação de erros. Use **NULL** para este parâmetro se esta for uma operação assíncrona para evitar resultados potencialmente errôneos.

Este parâmetro pode ser **NULL** somente quando o parâmetro _lpOverlapped_ não for **NULL** .

**Windows 7:** Este parâmetro não pode ser **NULL** .

Para mais informações, consulte a seção Observações.

`[in, out, optional] lpOverlapped`

Um ponteiro para uma estrutura [OVERLAPPED](https://learn.microsoft.com/en-us/windows/win32/api/minwinbase/ns-minwinbase-overlapped) é necessário se o parâmetro _hFile_ foi aberto com **FILE_FLAG_OVERLAPPED** , caso contrário, pode ser **NULL** .

Se _hFile_ for aberto com **FILE_FLAG_OVERLAPPED** , o parâmetro _lpOverlapped_ deverá apontar para uma estrutura [OVERLAPPED](https://learn.microsoft.com/en-us/windows/win32/api/minwinbase/ns-minwinbase-overlapped) válida e exclusiva ; caso contrário, a função poderá relatar incorretamente que a operação de leitura foi concluída.

Para um _hFile_ que suporta deslocamentos de bytes, se você usar este parâmetro, deverá especificar um deslocamento de bytes no qual iniciar a leitura do arquivo ou dispositivo. Esse deslocamento é especificado definindo os membros **Offset** e **OffsetHigh** da estrutura [OVERLAPPED](https://learn.microsoft.com/en-us/windows/win32/api/minwinbase/ns-minwinbase-overlapped) . Para um **hFile** que não suporta deslocamentos de bytes, **Offset** e **OffsetHigh** são ignorados.

Para obter mais informações sobre diferentes combinações de _lpOverlapped_ e **FILE_FLAG_OVERLAPPED** , consulte a seção Comentários e a seção **Sincronização e Posição de Arquivo** .

## Valor de retorno

Se a função for bem-sucedida, o valor de retorno será diferente de zero ( **TRUE** ).

Se a função falhar ou for concluída de forma assíncrona, o valor de retorno será zero ( **FALSE** ). Para obter informações de erro mais detalhadas, chame a função [GetLastError](https://learn.microsoft.com/en-us/windows/win32/api/errhandlingapi/nf-errhandlingapi-getlasterror) .
